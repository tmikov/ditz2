Running dz init in a directory below an existing dz/config.yaml creates a second project. Every later command then walks up and finds the nearer one, which is rarely what was wanted.

Nesting is legitimate for genuinely separate subprojects, so do not forbid it. Detect the parent and say so, with a flag to proceed.
