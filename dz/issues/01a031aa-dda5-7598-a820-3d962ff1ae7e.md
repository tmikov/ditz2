Running dz --json with no subcommand hits commanders missing-subcommand path, whose CommanderError message is the internal placeholder "(outputHelp)". That string ends up in the envelope:

  {"error":{"code":"USAGE_ERROR","message":"(outputHelp)"}}

The envelope is valid, stdout is empty and the exit code is 2, so nothing is broken. The message is just useless. Special-case it and say a subcommand is required.
