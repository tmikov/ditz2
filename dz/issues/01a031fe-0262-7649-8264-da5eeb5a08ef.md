README says free-form Markdown, preserved verbatim, the tool never reformats it. Three ways that is not true:

- parseIssue trims the body, so leading and trailing blank lines are lost.
- A body line reading exactly "## Log" truncates the body; the remainder is then parsed as log entries and usually errors.
- YAML comments and key formatting in the frontmatter do not survive a rewrite, since it is re-emitted from the parsed object.

The trim is load-bearing: it is what makes the round-trip law hold, because renderIssue re-inserts exactly one blank line on each side.

Correcting the README is obvious and I am doing it. Changing the behaviour is a decision, and I would not: the round-trip property is worth more than exact whitespace.
