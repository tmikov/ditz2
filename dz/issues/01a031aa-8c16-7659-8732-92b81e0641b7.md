When frontmatter id and filename stem disagree, readIssue correctly refuses the file, but findIssue resolves prefixes only over issues that loaded. So dz show <stem> reports NOT_FOUND, naming a file you can see on disk.

dz list and dz set behave correctly already: list warns with the true reason, and set fails rather than writing a second file. Only the show diagnostic is misleading.

Fixing it means letting findIssue see load failures, which is a rework of the lookup path.
