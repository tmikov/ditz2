renderWarnings formats "skipping {file}: {message}", but parse errors already begin with the filename, so the warning reads:

  dz: warning: skipping dz/issues/x.md: dz/issues/x.md: frontmatter id ...

More visible now that findIssue surfaces these errors through dz show as well. Either drop the prefix in renderWarnings or stop prefixing the filename in the parse errors; the second is riskier, since those messages are asserted on in tests.
