HANDOFF.md records `ui/tests/e2e.test.ts` as the one flaky UI file, failing on `expect(r.timedOut).toBe(false)`. It is not the only one.

Measured on master, running `npx vitest run --root ui --exclude 'tests/e2e.test.ts'` six times: two runs failed. Different tests each time, across three files —

- `close > passes a typed comment alongside the resolution` — `Cannot read properties of undefined (reading '1')`
- `the / filter field > narrows the list as it is typed` — `expected [] to have a length of 1 but got +0`
- `the form > moves focus with Tab and back with Shift-Tab` — `expected false to be true`

All three render through ink-testing-library and advance time with `settle()`, a fixed 25ms wait in `ui/tests/helpers.tsx`. A fixed delay against Ink's own render scheduling is the obvious suspect: under load one repaint has not landed when the assertion runs, and which test loses the race varies.

Not caused by the hermes-node work — the same rate reproduces on master with `dist/` untouched, and none of these files import anything that work changed.

Two things worth doing: correct HANDOFF.md, which currently sends the next person looking only at the pty tests, and replace `settle()`'s fixed wait with something that waits for the frame it needs rather than for a duration.
