Every mutating command is an unlocked read-modify-write: findIssue parses, a core function returns a new Issue, writeIssue renames over the old file. Two commands touching the same issue concurrently both succeed, and the later rename discards the earlier change.

Atomic writes prevent a torn file. They do not prevent a lost update.

This matters most for the agent workflow the spec puts first, where several commands may run in parallel against one project.

NEEDS A DECISION, not fixing yet. Options, roughly ascending in cost:
- Compare mtime and size between read and write, and fail with a retry-me error on a mismatch. Cheap, no new state, races only in a tiny window.
- An O_EXCL lock file per issue, or per project. Reliable, but needs stale-lock handling, which is its own problem.
- Accept it and document it. Defensible for a single-user CLI, not for the agent story.

I lean toward the first.

    Design settled and committed: docs/superpowers/specs/2026-08-24-single-lock-file-design.md. A single ephemeral dz/.lock serialising all mutating commands.

    This supersedes the hash compare-and-swap I recommended in the description above. That approach only narrows the race window rather than closing it, and does nothing for edit, where the window is however long a human leaves the editor open. Locking costs abandoned-lock handling, because Node has no flock and so the kernel cannot release on death, but that is the smaller cost.

    Resolved while reviewing the design:
    - edit commits by parsing the scratch file and writing through writeIssue, not by renaming the scratch over the target. rename is only atomic within a filesystem and fails EXDEV across one, verified here between a FUSE-backed checkout and btrfs, so committing by rename would have pinned the scratch to the issue filesystem. Reading it instead frees it to live in os.tmpdir.
    - Contention retries until DZ_LOCK_TIMEOUT_MS, default 2000, 0 meaning fail immediately. Failing instantly would push a retry loop onto every agent.
    - .lock joins config.local.yaml in the gitignore template.
    - LOCKED and CONCURRENT_MODIFICATION join the error codes and the schema enum. The schema has not shipped, so no version bump.
    - doctor and unlock share one is-abandoned predicate rather than each implementing the rules.

    Stays open until the lock ships.
