resolveAuthor rejects an author containing a newline or a double space, because the log grammar uses those as separators. probeVcsIdentity writes its result to config.local.yaml without that check.

So a git user.name containing a double space gives you a project that inits successfully and then fails every command that needs an author. Recoverable, since the error names the file, but the failure lands far from its cause.

Run the same check at init and warn there instead.
