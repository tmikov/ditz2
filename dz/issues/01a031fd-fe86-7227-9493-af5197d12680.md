Verified. Starting from a project with a customised dz/.gitignore and a hand-set author, "dz init --name second" produced:

- dz/.gitignore: the extra line was deleted. initProject rewrites the file unconditionally.
- dz/config.local.yaml: a hand-set author was replaced by the probed VCS identity.
- output said: initialized dz project "second", but config.yaml still says name: first, because initProject only writes config.yaml when absent. It reports a name it did not apply.

The unconditional .gitignore write was deliberate, for idempotence without VCS detection. Preserving other lines and only appending the missing one keeps that property.

Obvious parts: do not overwrite an existing config.local.yaml, preserve unknown .gitignore lines, and report the name actually in config.yaml.
